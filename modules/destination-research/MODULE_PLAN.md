# 目的地研究与证据审计模块：模块总规划

## 0. 文档信息

- 文档类型：模块级总规划
- 文档版本：v0.1
- 文档状态：当前模块设计基线，后续按正式决策持续更新
- 所属项目：[文旅口号创意工作台](../../PROJECT_PLAN.md)
- 对应总流程：研究计划与来源策略、深度资料采集、证据审计与目的地认知地图、研究充分性闸门与用户确认
- 当前目标：先确定模块契约、子模块边界和验收方式，再逐项设计执行方法

本文件是“目的地研究与证据审计模块”的独立总规划，持续记录模块应该解决的问题、交付结果、子模块边界和完成标准。后续正式确认的设计写入本文件；具体来源清单、搜索方法、采样方案、提示词、工具调用和存储结构，在对应子模块设计中单独确定。

## 1. 模块定义

### 1.1 一句话定义

目的地研究与证据审计模块负责主动搜集、整理和核查与目的地口号创作有关的信息，区分事实、官方定位、公众感知、系统推断和创意假设，最终向创意模块交付有证据支持的核心认知候选和研究充分性判断。

### 1.2 要回答的核心问题

这个模块必须帮助项目回答：

> 这个目的地有哪些内容值得被记住？这些内容的证据是什么？公众如何理解它？与其他目的地相比有什么区别？目前的研究是否足以进入创意阶段？

### 1.3 模块价值

这个模块不是资料汇编工具，也不是口号生成器。它的价值在于把分散的目的地信息转化为：

- 可追溯的事实和证据；
- 有边界的公众感知判断；
- 可比较的竞品表达信息；
- 有依据、可质疑的核心认知候选；
- 是否可以继续创作的明确判断。

## 2. 模块边界

### 2.1 负责的内容

- 根据已解析的官方征集要求制定研究任务；
- 确定需要回答的目的地研究问题；
- 主动搜集官方、历史、地理、文化、地名、居民、游客、媒体和竞品资料；
- 对具体主张进行证据提取和来源核查；
- 区分事实、官方愿景、公众感知、传说、推断和创意假设；
- 记录资料时效、来源性质、支持范围、冲突和缺口；
- 分析目的地的公众感知和当前旅游体验；
- 分析竞品口号、既有定位和表达拥挤区；
- 提炼多个核心认知候选及其证据和限制；
- 通过研究充分性闸门，向用户交付研究结果并接收纠正。

### 2.2 不负责的内容

- 直接确定最终口号文字；
- 对候选口号进行最终语言精修；
- 制定完整的目的地品牌战略或营销方案；
- 替用户决定目的地应该选择哪一种品牌取舍；
- 把未核实的信息包装成正式投稿阐述；
- 处理与口号创作无关的外部投稿行政事项。

## 3. 输入与输出契约

### 3.1 输入

模块启动时至少需要：

- 目的地名称和对象类型，如城市、景区、线路或活动；
- 已解析的官方征集要求、主题和文本约束；
- 口号用途、使用周期和目标受众；
- 已知的项目边界和用户补充信息；
- 前序模块提出的待研究问题。

用户补充的信息可以作为研究线索或待核查内容，但不能因为用户提供就自动视为已确认事实。

### 3.2 输出

一次完整研究至少应形成以下结果：

1. **研究任务简报**：研究目标、问题清单、重点范围和暂不研究内容；
2. **来源台账**：来源、发布者、时间、来源类型、适用范围和访问记录；
3. **主张与证据台账**：具体主张、证据摘录、来源关联、证据状态、冲突和允许用法；
4. **目的地事实地图**：历史、地理、文化、地名、人物、产业、场景和其他相关事实；
5. **公众感知地图**：居民、游客、媒体和官方定位分别如何描述或体验目的地；
6. **竞品表达地图**：相关目的地已经使用的口号、定位和高频表达；
7. **缺口与冲突清单**：尚未确认、来源不足、时效不明或互相矛盾的内容；
8. **核心认知候选**：每个候选的主张、证据、公众感知、差异化机会和限制；
9. **研究充分性报告**：可以进入创意、需要继续研究或暂不具备创作条件的判断；
10. **用户确认记录**：用户纠正、认可、否决和要求继续研究的内容。

## 4. 真实性与证据规则

本模块执行项目总规划中的真实性协议。除非后续模块明确收紧，不得降低以下要求。

### 4.1 以主张为单位审计

不把一整篇文章或一个网站整体视为可信。每个会影响研究结论、创意方向或投稿阐述的关键主张，都必须单独记录它的来源、支持内容和使用状态。

### 4.2 四种证据状态

- **已确认事实**：来源明确、内容与主张相符，没有未解决的可信反证，可以作为事实使用；
- **有来源的观点或感知**：包括官方定位、居民或游客表达、媒体印象和民间传说，可以使用，但必须标明性质和范围；
- **系统推断或创意假设**：由资料综合形成的判断，可以用于创意探索，但不能写成事实；
- **未核实或存在冲突的信息**：只能作为继续研究的线索，不得直接进入核心认知或正式投稿成果。

### 4.3 来源与主张必须匹配

官方资料优先用于确认官方要求、官方定位和正式项目；历史档案、地方志、博物馆、学术资料等优先用于历史和文化事实；居民、游客和媒体内容用于观察公众感知和实际体验。任何来源只能在它确实支持对应主张的范围内使用。

### 4.4 冲突、时效和不确定性必须可见

资料出现冲突时，模块必须继续核查、保留冲突或放弃该主张。过时信息、单一来源、样本有限的公众表达和无法确认的时间范围都必须被记录，不能隐去不确定性后形成确定结论。

### 4.5 不可违反的底线

- 不编造来源、数据、引语、典故、历史事实或研究结果；
- 不把模型记忆、搜索摘要或单个社交媒体内容当作已确认事实；
- 不把传说写成史实，不把官方愿景写成已经被游客验证的体验；
- 不用单个居民或游客的表达代表整个群体；
- 未经证实的唯一性、极致化和排名表达不得作为事实使用；
- 正式投稿阐述中的事实性陈述必须能够回到本模块的证据台账。

## 5. 子模块结构

### R0. 研究任务定义

把目的地类型、官方要求、传播任务和目标受众转化为研究目标、问题清单和范围边界。

输出：研究任务简报。

### R1. 研究问题与来源策略

确定需要回答的问题、资料类别、来源方向、来源优先级和记录方式。此处只形成策略，不直接假定某个来源已经证明事实。

输出：研究问题清单、来源策略和资料采集计划。

### R2. 资料采集

按研究计划搜集官方、历史文化、地名、公众感知、旅游体验、竞品和既有表达资料，保留原文、链接、时间和上下文。

输出：原始资料集和来源台账。

### R3. 主张提取与证据台账

从原始资料中提取可影响判断的具体主张，记录证据摘录、来源关联、证据状态和允许用法。

输出：主张与证据台账。

### R4. 证据审计与冲突处理

检查来源与主张是否匹配，识别重复转载、过时信息、单一来源、证据不足和相互冲突的说法，并决定继续核查、标注、保留或放弃。

输出：审计结果、冲突清单和事实缺口清单。

### R5. 公众感知与旅游体验分析

从居民、游客、媒体和其他公开表达中归纳目的地被如何理解、记住、体验和分享。个体表达不得直接升级为群体结论，分析必须说明时间和样本边界。

输出：公众感知地图和旅游体验观察。

### R6. 竞品与表达拥挤区分析

整理相关城市、景区和目的地已经使用的口号、定位、意象和高频词，判断哪些表达已经拥挤，以及目的地可能避开或重新解释的空间。

输出：竞品表达地图和表达拥挤区清单。

### R7. 核心认知候选提炼

将经过审计的事实、公众感知、体验和竞争信息综合为多个核心认知候选。每个候选必须说明：它是什么、依据是什么、为什么可能属于该目的地、与竞品有什么区别、有哪些限制。

输出：核心认知候选集和创意使用边界。

### R8. 研究充分性闸门与用户确认

向用户呈现研究摘要、证据状态、缺口、冲突和核心认知候选。根据用户纠正和选择，决定继续研究、回退核查，还是将研究结论交付给创意模块。

输出：研究充分性报告、用户确认记录和创作前提。

## 6. 模块工作回路

模块不是一次性搜索后直接交付，而是按以下回路运行：

```text
定义研究任务
→ 制定问题与来源策略
→ 采集资料
→ 提取主张并建立证据台账
→ 审计证据、处理冲突
→ 分析公众感知和竞品表达
→ 提炼核心认知候选
→ 用户确认
```

必要时允许以下回退：

- 发现关键事实缺口，回到资料采集；
- 发现来源无法支持主张，回到主张提取或来源核查；
- 发现冲突影响核心认知，回到证据审计；
- 用户否决核心认知，回到公众感知、竞品分析或继续研究；
- 研究无法支撑任何核心认知时，输出“暂不具备进入创意阶段的条件”。

## 7. 研究充分性判断

研究通过闸门不等于“搜集了很多资料”，而是至少满足以下条件：

- 官方要求和研究任务已经明确；
- 与候选核心认知相关的关键主张有清楚的证据状态；
- 事实、官方定位、公众感知、推断和创意假设已经分开；
- 主要冲突、缺口、时效和样本限制已经披露；
- 竞品表达和目的地差异化机会已经被检查；
- 每个核心认知候选都能说明依据、差异和限制；
- 用户已经有机会纠正事实、调整优先级或要求继续研究。

闸门状态暂定为：

- **可以进入创意阶段**：证据足以支撑至少一个核心认知候选，主要风险已披露，并完成用户确认；
- **需要继续研究**：存在会影响创意方向的关键缺口、冲突或来源问题；
- **暂不具备创作条件**：在当前范围和资料条件下，无法形成有足够依据的核心认知。

## 8. 用户、Agent 与 Skill 的职责

### 8.1 用户

- 提供目的地和官方要求的基本输入；
- 在研究闸门审阅核心事实、认知候选、缺口和冲突；
- 纠正错误、补充线索、调整优先级或要求继续研究；
- 确认哪些研究结论可以进入创意阶段。

### 8.2 Agent

- 编排 R0-R8 的执行顺序和回退；
- 调用搜索、资料处理和记录工具；
- 管理来源台账、主张台账、研究状态和版本；
- 向用户呈现可审阅的证据和认知摘要；
- 在证据不足或冲突未解决时停止进入创意阶段。

### 8.3 Skill

- 提供研究问题分类、资料分类和主张提取方法；
- 执行真实性与证据使用规则；
- 提供公众感知、竞品表达和核心认知提炼方法；
- 提供研究充分性判断和用户确认的输出格式。

## 9. 模块完成标准

一次研究任务完成时，必须能够回答：

- 我们研究了什么，为什么研究这些内容；
- 关键结论分别属于事实、观点、感知、推断还是假设；
- 每个关键事实和核心认知依据了哪些来源；
- 哪些内容仍然不确定或存在冲突；
- 目的地与竞品的表达差异在哪里；
- 哪些核心认知值得进入创意阶段，哪些不值得；
- 用户是否已经确认研究前提。

如果这些问题无法回答，模块不能标记为“研究完成”。

## 10. MVP 与后续实现

### 10.1 MVP

- 采用人工驱动的会话完成 R0-R8；
- 使用结构化 Markdown 保存来源和主张台账；
- 先验证一个真实城市或景区；
- 暂不实现复杂数据库、自动评分和多 Agent 拆分；
- 重点验证证据分类、冲突披露和研究闸门是否有效。

### 10.2 后续实现

方法通过真实案例验证后，再实现资料采集自动化、来源记录工具、持久化状态、检索辅助和 Agent 编排。具体实现顺序由 MVP 暴露的瓶颈决定。

## 11. 待讨论的子模块问题

后续应按 R0-R8 逐项确定：

- R0：最少需要哪些任务输入，目的地类型如何影响研究范围；
- R1：不同研究问题对应什么来源类别和搜索策略；
- R2：资料采集的范围、时效和来源优先级如何制定；
- R3：主张与证据台账的具体字段和记录格式；
- R4：如何处理来源冲突、转载、失效链接和不确定信息；
- R5：居民、游客和媒体内容如何观察而不夸大样本；
- R6：竞品范围如何确定，怎样识别表达拥挤区；
- R7：核心认知候选如何比较，如何避免把资产清单当认知；
- R8：研究充分性如何判断，用户确认页面或输出如何组织。
