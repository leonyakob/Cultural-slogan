## 一、题目与位置

第 6 题是 M3 六问的最后一题：**案例如何使用？**（前五问——合格方向定义、方向如何产生、方向差异审计、G2 运转、M3/M4 接口——已全部完成并确认，见 03 台账。）

台账原题"必须回答"：

- 案例是否进入 M3；
- 案例分析能否提炼可观察特征；
- 案例是否进入 M4 生成上下文；
- 案例如何用于批判和质量比较；
- 如何区分参考、借鉴、模仿和撞车；
- 案例资料与单次项目文档如何交接。

## 二、用户对案例库的期望（2026-09-29 用户原话要点，**已确认**）

用户明确表示期望案例库同时具备五种作用：

- **A 眼界基准**：见过好东西（创作团队知道"好"长什么样）；
- **B 质量参照物**：判断候选行不行时有客观锚（比差距）；
- **C 避坑清单**：知道已经有什么（防撞车、防同质）；
- **D 灵感触发物**：好案例激发创意；
- **E 方法研究素材**：从案例学"口号创作手艺"的通则（供用户研究方法论）。

**并且**（用户原话）：

> "又希望大模型能见过好口号后不受好口号禁锢，能创造出不次于好口号的口号。"

## 三、既有地基（此前已确认的结论）

1. 02 文档确认：**案例集 = 一批好口号，定位是"参考"不是"上界标尺"**——"上限"说法已被用户收回（已存在的好口号不是天花板，更好的口号可以超越）。"参考"的具体用法（生成侧？批判侧？两处分工？）悬置至今，正是第 6 题要了结的。
2. **历史敏感点（重要伤疤）**：M3 旧方案推翻的原始导火索之一，就是"机制清单（人格化/地名语言化/历史再造/生活方式/游客行动/场景化）是从经典案例倒推的表达策略分类"——即"案例→提炼规律→按规律生成"这个环路翻过一次车。旧方案产出物风格参见用户最初的反面教材："这么近那么美周末到临安"（把"这么近，那么美，周末到河北"换个地名，一眼假）。
3. 用户的项目总目标（02 原话要点）：M3/M4 跑完应产出**让人眼前一亮的、创意性的、发散性的、文学性的、朗朗上口的、易于传播的、而不是一看就是模仿现有口号的**候选。"一击即中"原则：每条候选都是深度研究后认真创作的结果。

## 四、Claude Code 的多轮尝试与失败（**均被用户否决**，仅供 Codex 避坑参考）

| 轮次 | 方案 | 用户否决理由（原话要点） |

**Claude Code 自认的失败原因**（供参考）：

- 把"案例如何使用"（动作设计题）当成了"案例放哪个模块"（物料分配题）来答；
- 抽象拆分导致套娃（每个子问题都是对"如何处理案例"的再抽象）；
- 给未想清楚的问题硬套假骨架（如"光谱两阈值"套"区分参考/借鉴/模仿/撞车"）；
- 收敛方向是被用户质疑逼出来的砍削（砍到"案例只做防撞车"——但防撞车只需要查重清单，不配叫案例库），不是想清楚后的设计。

## 五、Claude Code 的最后一轮分析（**未经用户确认**，仅为一家之言，Codex 可自由反驳）

按"大模型预训练已见过海量口号"这一事实逐项审计用户的期望：

- **A（眼界）对模型基本冗余**——模型不是没见过世面的人；但 A 背后可能藏一个真需求的变形：**校准**（把"你"认为哪些是好明确传给模型——"好"的标准是用户的私人判断，模型没有这个信息）；
- **B（质量参照）增量存疑**——模型判差距用的还是它自己的判断力；项目真正在用的质量标尺是用户在 G3 的反馈（淘汰/捞回信号），案例标尺的净增量在项目早期最大、后期趋零；
- **C（避坑）是刚需且唯一必须案例库在场的功能**——撞车检测需要明确可靠经用户确认的比对集（靠模型记忆查重有幻觉风险）；
- **D（灵感触发）可能是伪需求**——"创造不次于好口号的口号"是质量目标（由 M4 整套机制承担），"见过好口号后"是想象中通往质量的路，而案例当灵感种子产出的恰是案例变体（翻车环路起点）——质量目标被误认成了案例用法；
- **E（研究素材）是用户个人用途**，不需要系统设计（笔记本即可）。

由此推出的 tentative 结论（同样未确认）：真正配存在的可能不是"案例库"，而是两个小东西——**查重清单**（C）+ **用户认证的好口号小集**（A 的校准变形）；第 6 题或可缩水为小题、甚至并入 M4/M5 既有讨论。

**用户对此分析的反应**：未确认，且明确表示"Claude Code 没有很好的思路，一直在被牵着走"。
