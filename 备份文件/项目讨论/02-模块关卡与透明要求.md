## 0. 前提：已确认的概念区分

用户在流程中有两种存在方式：

- **决策关卡**（流程暂停权）：不等你明确表态，流程不能继续。数量少而关键。
- **在场透明**（随时纠偏权）：流程运行中，中间产物实时可审阅。连续、全程。
  - 对话形态下的含义：随时把台账/评估表摊开给你看，你随时可以打断、纠正、追问。

模块间衔接方式（已确认）：**只传文档，不传状态**。每个模块的输出文档就是下一模块的输入文档。

模块划分（已确认）：

```
M1 简章解析        官方征集令 → 约束矩阵 + 维度词表
M2 研究与证据      R0-R8（已有设计）
M3 认知与创意简报  证据台账 + 竞品地图 → 核心认知 → 创意方向清单
M4 口号生产       创意方向 → 候选池 → 内部批判预筛 → 少量候选
M5 验证与投稿     用户锁定方案 → 投稿阐述 → 就绪检查 → 成果包
```

（M1 不在本次梳理范围：简章解析基本是机械解析，产出约束矩阵后用户审一眼即可，关卡 = 约束矩阵确认。）

## 1. M2 研究与证据（R0-R8）

### 关卡

**G1 研究充分性闸门**（模块出口，R8，已在 MODULE_PLAN 定义）
- 你审阅：研究摘要、核心认知候选、证据强度、缺口与冲突清单
- 你表态：继续研究 / 纠正事实 / 调整优先级 / 确认进入创意
- 硬规则：未经你确认，不得进入 M3

### 在场透明（R0-R7 逐环节）

| 环节 | 你能实时看到什么 | 你的随时纠偏权 |
|---|---|---|
| R0 研究任务定义 | 研究目标、问题清单、"暂不研究"的范围 | 增删研究问题、改范围 |
| R1 问题与来源策略 | 来源优先级、搜索路径 | 补充来源线索（如你知道的本地号）、质疑某类来源的权重 |
| R2 资料采集 | 来源台账新增条目 | 指定某个来源必查/跳过 |
| R3 主张提取 | 每条主张的原文摘录、来源关联 | 质疑"这句话不算一个主张"之类的颗粒度问题 |
| R4 证据审计 | 证据状态标注、冲突标记 | 提供反证、判定冲突取舍（如两篇文章年代说法不一） |
| R5 公众感知分析 | 感知地图、样本边界说明 | 补充你亲历的感知、质疑样本代表性 |
| R6 竞品与拥挤区 | 竞品口号清单、拥挤区标注 | 补充竞品城市、修正拥挤判断 |
| R7 核心认知候选 | 每个候选的依据/差异/限制 | 否决某候选、要求深挖某方向 |

### 特别说明

R8 本身就是关卡 G1，所以 M2 内部透明要求集中在 R0-R7。R4（证据审计）是透明要求最高的环节——因为真实性协议要求冲突可见，你看不到冲突就无法行使判定权。

## 2. M3 认知与创意简报

### 关卡

**G2 创意简报确认**（模块出口）
- 你审阅：核心认知的最终取舍（哪些进入创作）、每个创意方向的说明（表达什么/依据/为何适合）
- 你表态：砍方向 / 合并方向 / 调整方向优先级 / 确认进入候选生成
- 硬规则：未经确认的创意方向不得开始生成候选

### 在场透明

| 环节 | 你能实时看到什么 | 你的随时纠偏权 |
|---|---|---|
| 核心认知收敛 | 从候选到最终取舍的推理：为什么砍掉某个认知 | 捞回被砍的认知、质疑砍的理由 |
| 创意方向生成 | 每个方向的构思路径（人格化/地名语言化/历史再造/生活方式等机制） | 提出你想要的方向类型、否决某机制 |
| 方向风险标注 | 每个方向的限制与风险（同质化/牵强/证据弱） | 决定"带病推进"还是"规避" |

### 特别说明

M3 是"从事实到创意"的换轨点，透明要求的核心是**取舍推理可见**——不只是结论（选了 3 个方向），而是淘汰过程（8 个候选认知怎么死的）。这直接对齐 PROJECT_PLAN 4.7"允许淘汰方向，并说明淘汰依据"。

## 3. M4 口号生产

### 关卡

**G3 候选确认与方案锁定**（模块出口，分两步）
- 第一步·候选筛选：你审阅内部批判后的少量候选 + 全部淘汰理由，捞回被误杀的
- 第二步·方案锁定：你从候选中选定项目规定数量的方案集，或要求定向优化再一轮
- 硬规则：未经你选定，不得进入 M5 生成正式阐述

### 在场透明

| 环节 | 你能实时看到什么 | 你的随时纠偏权 |
|---|---|---|
| 候选生成 | 按方向组织的候选池（不是无差别句子列表） | 要求某方向加产、停产 |
| 内部批判 | 每条候选的批判记录：地域绑定/事实支撑/语言自然度/传播性/同质化/情绪承诺等逐项评估 | 质疑某条批判标准用错了（如"这句其实不土"）、推翻单项淘汰 |
| 预筛结果 | 入围/淘汰名单 + 淘汰理由 | 捞回、要求复议 |
| 定向优化 | 每轮修改的版本差异与修改原因 | 随时改变偏好、推翻上一轮约束 |

### 特别说明

M4 是用户介入密度最高的模块——因为语言审美的主观判断全在这里。PROJECT_PLAN 7.2 的质量标准（记忆机制、情绪承诺、母题延展）多数在 M4 的批判环节执行。内部批判透明还有一个特殊价值：**批判标准本身也在演进**（呼应诉求 2 的方法开放性），你看得到批判过程才能说"这个标准以后别用了"。

## 4. M5 验证与投稿

### 关卡

**G4 投稿包最终确认**（全流程终点）
- 你审阅：最终方案集、每条的投稿阐述、规则符合性检查结果、风险说明
- 你表态：修正后确认 / 通过
- 硬规则：只有你确认的投稿包才算最终成果；验证不通过则解除锁定回到 M4

### 在场透明

| 环节 | 你能实时看到什么 | 你的随时纠偏权 |
|---|---|---|
| 投稿阐述起草 | 每条阐述草稿、每个事实句对应的证据台账编号 | 要求改写语气、剔除某事实 |
| 规则符合性检查 | 逐项检查结果（字数/格式/主题/原创性） | 对模糊规则做出你的裁决（如"12字含不含标点"） |
| 撞车与风险检查 | 已有口号撞车比对结果、文化敏感性、过度承诺风险 | 接受/拒绝某风险 |
| 成果包组装 | 最终文档结构 | 要求调整成果包内容 |

### 特别说明

M5 的透明要求有一个特殊点：**阐述中的每个事实性陈述必须能指回证据台账**（PROJECT_PLAN 阶段 10 的硬要求）。所以透明不只是"给你看草稿"，而是"给你看草稿 ↔ 证据的对照关系"。这是全流程真实性协议的最后一道闸。

## 5. 汇总：五关卡 × 透明主线

| 关卡 | 位置 | 守的是什么 |
|---|---|---|
| G0 约束矩阵确认 | M1 出口 | 全流程的源头基准；含模糊规则裁决权（如字数口径） |
| G1 研究闸门 | M2 出口 | 创作前提的事实基础 |
| G2 简报确认 | M3 出口 | 创意方向的取舍权 |
| G3 候选与锁定 | M4 出口 | 语言与审美的最终裁决权 |
| G4 投稿确认 | M5 出口 | 对外提交的最后责任 |

透明主线：M2 重证据与冲突可见 → M3 重取舍推理可见 → M4 重批判过程可见 → M5 重事实↔证据对照可见。四个模块各有一条"最不能省的透明"。

## 6. 已确认的结论（2026-09-24）

1. **G3 保持两步，但允许快进**：第一轮审淘汰名单（误杀救济），第二轮锁定方案；若无捞回，用户可当场声明"没有捞回，直接锁定"，两步退化为一步。误杀救济永远在锁定之前。
2. **G0 成立**：M1 约束矩阵确认为第五关卡。理由：源头数据错误则全部下游检查在错误基准上运行；且模糊规则（"12字含不含标点"）的解释权只能归最终署名提交的用户。
3. **分层标准化**：五个跨模块接口文档（约束矩阵、证据台账、弹药库、候选池与批判记录、投稿包）强制固定格式——它们是衔接载体、跨会话恢复的锚点、事实指回的编号体系，也是将来固化与复用的资产；模块内部中间产物不强制格式（对话随聊，结论归档进接口文档即可）。（注：原清单中的"创意简报"已随方向层一起取消，由"弹药库"顶替接口位。）

## 7. 创意保护四对策（2026-09-24 确认）

背景：用户提出关键质询——这套约束体系会不会导致口号中规中矩、没有灵气。诊断：现有设计"淘汰侧精细、发散侧粗糙"，输出会向安全公约数收敛。已有三道防线（4.6 发散与批判分离、7.2 两项豁免、G3 捞回权），但仍有三个泄漏通道（负面过滤器的数学、LLM 均值本能、可辩护性文化渗透到口号正文）。补四条对策：

1. **陈词滥调基线**：正式生成前，先故意产出一批"最可预测的口号"并显性标记为基线/拥挤区。创意度的操作定义 = 偏离基线且仍然成立。反同质化从原则变成可执行的参照系。（归 M4，前置依赖 M3 的拥挤区分析）
2. **软标准永不单独淘汰**：硬规则（字数、合规、事实错误、撞车）才有一票否决权；语言自然度、情绪等软标准只标注不淘汰，基于软标准的淘汰权只属于用户。客观的归 AI，主观的归人。（归 M4 批判环节）
3. **亮点保护通道**：单项冒尖但带短板的候选，批判环节必须走"修复通道"——给出修法而非直接处决。"很强但有缺陷"不得输给"平庸但无错"。（归 M4 批判环节）
4. **大胆档配额**：每个创意方向的候选池强制包含刻意冒险的候选，明标风险等级。用户看到的永远是风险光谱，不是过滤器消化后的安全品。（归 M4 生成环节，M3 创意方向需带风险档位说明）

## 8. 模块结构重组（2026-09-24 确认）

讨论过程中推翻了原"五个模块"的部分划分：

1. **认知收敛（原 M3 的 C1）单独成模块**。用户判断：研究之后、创作之前，认知收敛是独立环节，不做 M2 的附属（R7.5）也不和创意简报缝在一起。它处理的是"哪些核心认知值得进入创作"——证据强度×公众感知×差异化空位的收敛判断。
2. **旧 M3 草案（认知与创意简报）整体推翻重来**，重新深度讨论。推翻原因：用户对"机制清单（人格化/地名语言化/历史再造/生活方式/游客行动/场景化）是从经典案例倒推的表达策略分类"这一方法论前提本身持怀疑态度，而非对机制的使用方式不满意。旧草案的"认知×机制矩阵匹配"被判断为伪问题：好创意方向是从认知里长出来的，不是矩阵里筛出来的；系统化遍历的组合恰恰产出陈词滥调基线本身。

重组后的模块序列（编号待定稿）：

```
M1 简章解析 → M2 研究与证据（R0-R8）→ 认知收敛（独立模块，原 C1）
→ M3' 创意简报（推翻重设计中）→ M4 口号生产 → M5 验证与投稿
```

关卡相应变化：G1 从"确认认知候选"移到认知收敛模块出口，含义变为"确认收敛后进入创作的核心认知"。

## 9. M3 重新讨论：起点问题与用户理想结果（2026-09-24）

### 用户对 M3 理想结果的定义（原话要点）

M3 跑完的理想结果：产出一堆**让人眼前一亮的、创意性的、发散性的、文学性的、朗朗上口的、易于传播的、而又不是一看就是模仿现有口号的**候选，供用户选择。反面案例：`这么近那么美周末到临安`——把"这么近，那么美，周末到河北"换个地名，一眼假。

### 待重新讨论的起点问题（不预设分类框架）

- Q1：M3 到底在解决什么问题（"翻译认知"还是"确定这场仗往哪打"还是别的）；
- Q2：从确认过的核心认知到第一个创意方向之间，真实发生的是什么（直觉/类比/手感要不要在流程里有位置）；
- Q3：创意方向的"好"由什么构成（是否由后续环节的产出口号质量定义，而非简报长相）；
- Q4：基线（M1/M2 传来）和维度词表在 M3 里是约束、素材还是检验器；
- Q5：M3 要不要保持"模块"形态（还是结构化的共创对话+结论沉淀）。

### AI 当前倾向（待用户检验）：M3 最可能的形态是"结构化共创对话+结论沉淀"而非流水线；流程只保证对话不散（有议程、结论落简报、险档不被聊死），不替代对话本身。

### 讨论推进中的新结论（2026-09-24）

1. **砍掉"创意方向"中间层的结构讨论**：用户理想结果是"发散性、眼前一亮"的口号直供选择，"方向层"会压窄发散。AI 提出甲（认知→方向→口号）/乙（认知→口号，方向仅事后归因）/丙（乙+基线对照+险档配额，无方向层）三结构，倾向丙。用户以"都不满意又说不出优化方向怎么办"质询丙的软肋，AI 给出四条补救路径（比较法/淘汰侧反推/AI 主动试错/回认知层诊断）+ 一次前置"口味校准探针"。
2. **用户否决"样稿探针"，并提出两条根本原则**：
   - **照猫画狗风险**：用户了解大模型行为——一旦在探针里显性化口味（选中某几条），后续生成大概率围绕选中样稿反复模仿，发散性死亡。口味显性化反而成为收窄的种子。
   - **"一击即中"原则**：用户不要 MVP 式小步试错迭代，要的是**口号产出即最好**——每一条候选都必须是深度研究后认真创作的结果，而不是随意编写用来探路的敷衍品。即使最终都不满意，候选本身的质量和诚意也必须成立。
3. **由此确认 M3/M4 设计的硬约束**（结构丙基础上的修正方向）：
   - 不设口味前置显性化环节（无探针、无方向确认）；
   - 每一轮候选产出都是全质量生成——不存在"草稿轮""探路轮"，被淘汰也只是因为不够好，不是因为"还没认真做"；
   - 优化循环（用户说不满意但说不出方向时）依赖：比较法反馈、淘汰/捞回信号、AI 差异化试错、必要时回认知层诊断——**不依赖用户预先给出方向**；
   - 生成侧的纪律：深度研究输入（证据台账+基线对照+险档配额）保证下限，发散结构保证上限，任何一条候选的诞生都能追溯到"依据什么认知、避开什么俗套、取什么险"。

### M3 弹药库方案：概念确认与"非最优"标记（2026-09-24）

> **【已废弃标记 2026-09-29 补录】本节方案已于 2026-09-24 Codex 会话中被用户确认舍弃：用户判断"越改越差，还不如最初的创意方向层"，Codex 提出恢复方向层（废弃固定机制清单）方案获用户确认（"整体看起来没什么毛病"），M3 转入六问重设计。本节保留作历史记录；接口位由方向卡集顶替（见 03 台账补录裁决）。本节"接口级承诺"三字段（认知编号、证据指回、task_id/destination）由方向卡自然继承。】

1. **概念已确认**：弹药库 = 料不是路线。它对已审计事实做**创作价值的再组织**（意象/引语/细节/情绪内核），不产生新事实、不预设生成路线；生成可自由混用多个认知的弹药。与被否决的"创意方向层"（约束打法）方向相反——料越全打法越自由。链条定稿表述：`G1 确认的认知 → 弹药库（附证据编号）→ 生成（自由用弹药+强制险档配额，无预设路线）→ 候选 → 批判（事后归因）`。表述事故已纠正："组合与险度"改为"自由使用弹药+强制险档配额"，避免与方向层混淆。
2. **方案状态：标记为"暂定非最优"**。用户认可概念但判断不是最优方案，暂提不出更好方案。处置方式（本轮确认）：**接受暂定方案 + 文档挂"非最优，待更好方案可替代"标记，继续推进后续讨论，不搁浅在等最优解上**。触发替代的条件：后续 M4/M5 讨论或临安实跑中自然涌现更优结构时，回改本节。

### 交接介质定案（2026-09-24）

**规则：模块交接只用文档，不依赖对话记忆。** AI 曾提出"同会话内轻交接（对话记忆）+跨会话重交接（文档）"的分层方案，以及"产出物文档化、纪律写方法文档"的二分法，均被用户指出自相矛盾（"纪律写在方法文档里"本身就是文档化）并否决。定案理由：会话边界不可预测（断网/误操作/上下文压缩），对话记忆作为交接介质不满足"稳定产出"的要求；上下文压缩造成的失真比丢失更难察觉。

执行口径：
- 模块间传递的一切内容——产出物、结论、判断、执行纪律——均以文档为载体；
- 对话记忆只是实时通信管道，不承担交接职责，不持有任何必须存活的内容；
- 方法/规则文档与产出文档都是文档，不设"轻重交接"之分；
- 证据链要求不变：能进正式投稿阐述的事实，必须能指回证据台账（文档编号）。

由此"模块"的表述修正为：**模块 = 值得独立命名与审阅的阶段；其必须文档化的产出物构成与其他模块的接口。**

## 10. M1 简章解析内部运转（2026-09-24 确认）

四步骤：S1 规则抽取（硬规则/主题要求/评价倾向/程序事实四类入表）→ S2 冲突与模糊识别（产出待裁决清单，每条附 AI 解读建议+备选解读）→ S3 独家素材捞取（征集令里的城市特色数据转 M2 素材库）→ S4 约束矩阵组装（固定格式接口文档，含 task_id/destination/硬规则表/维度词表/评价倾向/待裁决项/时效状态）。

两项用户裁决：

1. **S2 裁决时点：最终定案为攒到 G0 批量裁决**（用户先倾向"发现即问"，了解三项弊端——打断节奏/上下文碎片化/前后裁决被新信息推翻——后改回批量）。执行口径：解析过程中发现的模糊项**不中途打断用户**，全部记入待裁决清单，每条附 AI 解读建议+备选解读；G0 关卡时连同约束矩阵全量摊开，标注条目间联动关系，用户整体裁决。
2. **时效状态：不自动终止，升级用户裁决**。"已截止"有三种可能（真结束/延期/另有所图），M1 只摆事实不做去留判断。
